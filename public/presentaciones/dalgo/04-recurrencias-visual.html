Ver una recurrencia mientras corre

La guía escrita explica qué es una relación de recurrencia. Esta página la pone en movimiento: seis mecanismos que normalmente hay que armar en la cabeza — la delegación, la pila, el árbol de llamadas, los dos índices, la tabla que se llena— dibujados paso a paso, con los controles en sus manos.

Fuerza bruta y programación dinámica no son dos algoritmos. Son la misma recurrencia evaluada de dos maneras. Todo lo que sigue existe para que esa frase se vea.

Bajada

01

El gerente perezoso, en cadena

Usted solo sabe tomar una decisión: aportar el factor n. Todo lo demás lo delega a un clon idéntico, y confía en su postcondición sin preguntarle cómo lo hizo. Eso es la fe recursiva. Baje paso a paso y note que la cadena primero se estira completa hasta el caso base y solo entonces empieza a devolver.

Qué está pasando

La recurrencia

fact(n) = {
  1              si n = 0
  n · fact(n−1)  si n > 0
}

Regla que se está viendo

Nadie devuelve nada hasta que alguien llega al caso base. Sin caso base, la cadena de clones no termina nunca.

03

La pila: dónde vive el «después»

Cuando un gerente delega, no desaparece: queda congelado con un hueco por llenar (4 + ▢). Ese estado congelado ocupa memoria. Por eso mult(4,b) es O(b) en tiempo y O(b) en espacio, aunque no guarde ningún arreglo.

05

¿Cuándo sirve memoizar?

No siempre. La memoización solo cobra cuando el árbol de llamadas repite estados. Antes de aplicarla, dibuje el árbol y busque repeticiones: si es una cadena, no hay nada que ahorrar.

06

Palíndromo: cuando el estado necesita dos números

El subproblema no es «una cadena más corta»: es un segmento de la misma cadena. Y un segmento no se identifica con un número, sino con dos: dónde empieza y dónde termina. Fíjese en el último paso de una palabra de longitud par — ahí se ve por qué el caso base es i ≥ j y no i = j.

Qué está pasando

La recurrencia

pal(i,j) = {
  true                si i ≥ j
  s[i]=s[j] ∧
    pal(i+1, j−1)     si i < j
}
respuesta = pal(0, n−1)
07

Suma máxima: el significado insuficiente, en vivo

El primer intento — mejor(i) = la mejor suma en a[0..i] — no cierra, porque el clon devuelve una suma que puede estar lejos de i y no ser extensible. La solución es hacer la postcondición más específica: term(i) = la mejor suma de un subarreglo que termina exactamente en i. Con esa promesa, la transición se escribe sola.

a[i] positivo a[i] negativo mejor subarreglo que termina en i

Qué está pasando

Estado del gerente

—term(i)
—máximo hasta ahora

La recurrencia

term(i) = {
  a[0]                si i = 0
  max( a[i],
       a[i]+term(i−1) )  si i > 0
}
respuesta =
  max{ term(i) : 0 ≤ i < n }

La respuesta no siempre es f(n). Aquí el mejor subarreglo termina en alguna posición y no sabemos cuál, así que la respuesta es una agregación sobre todos los estados, no una llamada única. Responda siempre la pregunta 6 de forma explícita.

08

Cuatro formas de romper una recurrencia

Cada una tiene un síntoma reconocible. Aprender a nombrar el síntoma es más útil que memorizar la solución.

◆

Lo único que cambió fue la libreta

Compare las dos versiones. Las líneas verdes son idénticas: el caso base y la transición, es decir, la recurrencia completa. Lo morado es todo lo que agrega la programación dinámica.

Fuerza bruta

def fib(n: int) -> int:
    if n <= 1:
        return n

    return fib(n-1) + fib(n-2)

Programación dinámica

def fib_memo(n, memo=None):
    if memo is None: memo = {}
    if n <= 1:
        return n
    if n not in memo:
        memo[n] = \
            fib_memo(n-1,memo) + fib_memo(n-2,memo)
    return memo[n]

Por eso escribir bien la recurrencia es lo que importa. Si la tiene, la programación dinámica sale sola: es la misma definición, evaluada sin repetir trabajo.
