I

El problema

Qué promete un diccionario, cuánto cuesta cumplirlo con lo que ya conocen, y la idea del archivador que lo cambia todo.

Lo que ya usaban

Un mismo TAD detrás de set y dict

El diccionario

un conjunto de claves, cada una con un valor

insertar(k, v)  guarda v asociado a k
                (si k estaba, reemplaza)
buscar(k)       el valor de k, o «no está»
borrar(k)       quita k y su valor

Un conjunto es un diccionario sin valores.

vistos = set()
conteo = {}

    ...

Todo el semestre lo ha usado. Lo que cambia de una implementación a otra es cuánto cuesta cada operación.

La analogía

El gerente, ahora con un archivador

1 · Una pila

sobre el escritorio

Guardar es inmediato. Encontrar una carpeta obliga a revisarlas todas.

Θ(n) por búsqueda.

2 · Un cajón por código

direccionamiento directo

La carpeta k va en el cajón k. Buscar es abrir un cajón: Θ(1).

Con cédulas de 10 dígitos: 10¹⁰ cajones para unas 300 carpetas.

3 · m cajones y una regla

la función hash h

Mirando solo el código, h(k) dice el cajón. Guardar y buscar: calcular h(k) y abrir ese cajón.

Con la opción 3, dos carpetas distintas pueden ir al mismo cajón: una colisión. No es un error: es inevitable.

La regla del gerente

Tres condiciones sobre h

1

Determinista

La misma carpeta va siempre al mismo cajón. Si no, la carpeta se pierde.

2

Rápida

Calcular h(k) cuesta Θ(1), o lo que mida la clave si es una cadena.

3

Pareja

Reparte las carpetas de forma uniforme. Si casi todas caen en el mismo cajón, el archivador vuelve a ser una pila. Esta es todo el arte.

La función hash

Del número al cajón, de la cadena al número, y lo que hace Python cuando usted escribe hash(k).

El método de la división

h(k) = k mod m: el valor de m importa

claves: 10 · 20 · 30 · 40 · 50 · 60

Polinomial, con Horner · B = 31, m = 1009

def hpol(s, B=31, m=1009):
    h = 0
    for c in s:
        h = (h * B + ord(c)) % m
    return h

La cadena es un número en base B. Horner lo calcula sin potencias, en Θ(L).

Con la suma, todos los anagramas chocan.

Lo que hace Python

Tres cosas que pasan al escribir hash(k)

>>> hash(5)
5

Un entero pequeño es su propio hash.

Los grandes se reducen módulo el primo 2⁶¹ − 1. Y por convención, hash(-1) == -2.

>>> hash('amor')
cambia en cada
ejecución

Desde Python 3.3, el hash de str se mezcla con un valor aleatorio al arrancar.

Constante dentro de una ejecución. Se fija con PYTHONHASHSEED. El porqué, al final.

>>> {[1, 2]: 'x'}
TypeError:
unhashable type:
'list'

Solo los inmutables son clave. Las tuplas sí, las listas no.

III

Colisiones

Dos políticas: el cajón admite varias carpetas (encadenamiento), o admite una sola y se prueba el siguiente (direccionamiento abierto). Y el invariante que hace correcta a cada una.

El método

Seis preguntas para una estructura

  1. Contrato. ¿Qué operaciones promete y qué devuelve cada una?
  2. Invariante. ¿Qué es siempre cierto entre una operación y la siguiente?
  3. Ubicación. Dada una clave, ¿dónde la busco?
  1. Conflicto. ¿Y si el lugar ya está ocupado por otra clave?
  2. Parada. ¿Cuándo sé que la clave no está?
  3. Crecimiento. ¿Cuándo está demasiado llena?

La 2 es la central: el invariante permite que buscar se detenga temprano y aun así sea correcta.

Costo: en función de α = n/m, el factor de carga.

Ejercicio 1 · encadenamiento

Cada cajón es una lista

InvarianteToda clave está en la lista del cajón h(k), y aparece una sola vez en la tabla.
ConflictoLa nueva clave se agrega a la misma lista. No hay que buscar otro lugar.
ParadaAl encontrar k, o al llegar al final de la lista: entonces k no está en ninguna parte.
def buscar(self, k):
    for clave, valor in self._cajon(k):
        if clave == k:   # clave, no hash
            return valor
    return None
self.cajones = [[] for _ in range(m)]
# NO [[]] * m: m referencias a UNA lista

Si las n claves se reparten parejo, cada lista tiene α elementos: buscar cuesta Θ(1 + α).

Error común

for clave, valor in self._cajon(k):
    if hash(clave) % self.m == \
       hash(k) % self.m:   # INCORRECTO
        return valor

Dentro de un cajón todas tienen el mismo h: eso es colisionar. Esta versión devuelve la primera clave del cajón.

Dentro del cajón se compara con ==.

Ejercicio 2 · sondeo lineal

Una clave por celda, y se prueba la siguiente

Cada celda está VACÍA, OCUPADA o BORRADA. Para la clave k se revisan, en orden:

h(k), h(k)+1, h(k)+2, …   (mod m)

Es la secuencia de sondeo. Cada celda revisada es un sondeo, incluida aquella donde se detiene.

buscar para al encontrar k, al encontrar una VACÍA, o tras revisar las m celdas.

Invariante

Si k está en la celda p, ninguna celda de su secuencia anterior a p está VACÍA.

¿Por qué parar en una VACÍA? Si k estuviera más adelante, al insertarla se habría quedado en esa celda, que estaba libre.

Demo en vivo · sondeo lineal con m = 11

Borrar con VACÍA rompe la búsqueda de otra clave

La lápida, y su error

Para buscar está ocupada; para insertar, libre

Una celda BORRADA, o lápida †, dice: aquí hubo algo; siga buscando.

Pero insertar en la primera lápida exige terminar de buscar antes: hasta una VACÍA o hasta revisar las m celdas.

Primero confirmar que k no está. Después escoger dónde ponerla.

Error común · inserta sin terminar de buscar

def insertar(self, k):      # INCORRECTO
    i = hash(k) % self.m
    while (self.celdas[i] is not VACIA and
           self.celdas[i] is not BORRADA and
           self.celdas[i] != k):
        i = (i + 1) % self.m
    self.celdas[i] = k

Si k estaba detrás de la lápida, queda dos veces. Al borrarla, la otra copia sigue apareciendo.

Ejercicio 3 · crecer a tiempo

Picos cada vez más caros, y cada vez más raros

Empieza con m = 8. Si la nueva clave haría α > 2/3, se crea una tabla de 2m y se reubican todas: k mod m cambió con m.

inserción m después

Costo = 1 por la clave nueva + 1 por cada clave reubicada. Los siguientes picos: inserción 43, luego 86…

Análisis amortizado · método agregado

Sumar todo y dividir: menos de 3 por inserción

Al insertar N claves: N costos de 1, más las reubicaciones. La última reubica a lo sumo N; la anterior, N/2…

reubicaciones ≤ N + N/2 + N/4 + …
              < 2N
costo total   < N + 2N = 3N
por inserción < 3

Crece cada pocas inserciones y cada vez reubica todo: Θ(N²) en total.

Multiplicar funciona porque los picos se vuelven más raros al mismo ritmo al que se vuelven más caros.

list.append hace lo mismo

Sin espacio, pide un bloque proporcional al tamaño actual y copia todo. Su O(1) de la presentación 4 es amortizado, no en cada llamada.

El amortizado no promedia sobre entradas posibles: promedia sobre las operaciones de una misma ejecución, y vale para cualquier secuencia.

Colisiones a propósito

2003 · Crosby y Wallach

USENIX Security. Claves escogidas para caer en el mismo cajón: cada inserción Θ(n), construir la tabla Θ(n²). Contra Perl, Squid y Bro.

2011 · 28C3, Klink y Wälde

PHP, Java, Python. Una petición HTTP con miles de campos que colisionan ocupa un núcleo del servidor.

Python

Hash aleatorio para str y bytes, por defecto desde 3.3. Es el hash('amor') que cambia.

Java 8

Un cajón con 8 claves se vuelve árbol rojo-negro (con al menos 64 cajones): el peor caso de buscar baja a Θ(log n).

Carter y Wegman, 1979

Hashing universal: la función se escoge al azar

ha,b(k) = ((a·k + b) mod p) mod m

p primo mayor que cualquier clave · a al azar en [1, p−1] · b al azar en [0, p−1]

≤ 1/mprob. de que dos claves distintas colisionen

El azar ya no está en las claves, que el adversario controla, sino en la función, que el adversario no conoce.
