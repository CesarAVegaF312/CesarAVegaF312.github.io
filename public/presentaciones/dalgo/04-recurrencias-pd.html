I

La recurrencia

Antes de escribir código: qué es una relación de recurrencia, por qué se escribe primero, y el método de seis preguntas para llegar a ella.

Distinción que cuesta cara

Dos cosas distintas, y una va primero

Relación de recurrencia

una definición matemática

fact(n) = {
  1              si n = 0
  n · fact(n−1)  si n > 0
}

Dice cómo se relaciona la respuesta con la de un problema más pequeño. No dice cómo calcularla.

Función recursiva

un programa que se llama a sí mismo

def fact(n):
    if n == 0:
        return 1
    return n * fact(n-1)

Es la traducción de la relación anterior. Sale sola cuando la relación ya está escrita.

Primero la relación. Después el código. Siempre en ese orden.

La analogía

Usted es un gerente con una sola habilidad

  • El clon recibe un problema estrictamente más pequeño.
  • Usted no puede preguntarle cómo lo hizo. Confía en lo que promete su postcondición.
  • Usted combina lo que le devuelve con su propia decisión.
  • Hay problemas tan pequeños que no requieren delegar: los casos base.

Fe recursiva

Usted es fact(5). Su única decisión: «yo aporto el factor 5». Delega fact(4).

No le importa cómo el clon calcula 24. Solo que su postcondición promete devolver 4!.

Multiplica 5 · 24 = 120 y entrega.

El método

Seis preguntas, en prosa, antes del código

  1. Estado. ¿Qué parámetros describen un subproblema?
  2. Significado. ¿Qué devuelve f? Una frase precisa.
  3. Decisión. ¿Qué opciones tengo aquí?
  1. Transición. ¿A qué estado más pequeño llego y cómo combino?
  2. Caso base. ¿Dónde la respuesta es trivial?
  3. Respuesta. ¿Qué llamada resuelve el original?

Regla de oro: si no puede escribir la frase de la pregunta 2, no continúe. La pregunta 2 es la postcondición.

II

El trabajo repetido

Qué pasa cuando una llamada hace dos llamadas, por qué eso explota, y la observación de una línea que lo arregla.

Ejercicio 3 · Fibonacci

Una recurrencia que delega dos veces

fib(n) = {
  0                        si n = 0
  1                        si n = 1
  fib(n−1) + fib(n−2)      si n > 1
}

Dos casos base, no uno. La transición mira dos estados hacia atrás, así que necesita dos puntos de apoyo.

Si solo existiera fib(0), entonces fib(1) llamaría a fib(−1) y la cadena no vuelve.

La traducción, literal

def fib(n):
    if n <= 1:
        return n
    return fib(n-1) + fib(n-2)

Es correcta. Y es inservible para n = 50. La siguiente diapositiva muestra por qué.

memoización · de memo, nota

El punto más importante del curso

La recurrencia no cambió

Fuerza bruta

def fib(n):
    if n <= 1:
        return n


    return fib(n-1) + fib(n-2)

Programación dinámica

def fib(n, memo=None):
    if memo is None: memo = {}
    if n <= 1:
        return n
    if n not in memo:
        memo[n] = \
            fib(n-1,memo) + fib(n-2,memo)
    return memo[n]

Fuerza bruta es la recurrencia evaluada ingenuamente. Programación dinámica es la misma recurrencia evaluada sin repetir trabajo.

Antes de memoizar

¿Hay algo que repetir?

La memoización solo ayuda cuando el árbol de llamadas tiene estados repetidos. En una cadena, el diccionario cuesta memoria y no ahorra nada.

III

Memoización y tabulación

Los dos problemas del taller. La misma recurrencia, dos órdenes de llenado, y las tres razones por las que se elige uno u otro.

Problema 1 del taller

Sistema de monedas

Dadas denominaciones M = [m₁ … mₙ] y un objetivo C, halle el mínimo número de monedas que suman exactamente C.

Entrada:  11
          1 5 10
Salida:   2

Si no existe combinación: NO ES POSIBLE.

Las seis preguntas · estado de dos dimensiones

1 Estado(i, c): puedo usar las primeras i denominaciones y me falta formar c. Dos parámetros.
2 Significadof(i,c) = mínimo de monedas que forman exactamente c usando solo las primeras i denominaciones
3 Decisión¿uso la denominación mᵢ, o la descarto?
4 Transiciónf(i,c) = min( f(i−1,c) , 1 + f(i, c−mᵢ) )
5 Caso basef(i,0) = 0 · f(0,c) = ∞ para c > 0
6 Respuestaf(n, C) — la esquina de abajo a la derecha

En la matriz, las filas son los valores c y las columnas las denominaciones. El segundo término se queda en la misma columna: por eso la moneda se puede repetir.

Memoización y tabulación llenan las mismas celdas de la misma matriz con la misma recurrencia. Lo único que cambia es quién decide el orden.

Todo queda en ∞ → NO ES POSIBLE, y le bastó con mirar un tercio.

La tabulación llena las 48 o 63 celdas siempre. Ese es el precio de no tener que pensar en qué es alcanzable — y a cambio no apila nada y se puede comprimir.

El requisito de la tabulación

Dos dependencias: la de arriba y la de la izquierda

Los dos errores no fallan: mienten. Un orden malo lee celdas vacías; la diagonal resuelve otro problema. En ninguno de los dos casos hay excepción — solo un número equivocado. Con M=[1,5,10] y C=11 ambas versiones dan 2 y el error pasa desapercibido; con C=3 dan 3 contra NO ES POSIBLE.

El argumento práctico

El muro que solo golpea a la recursión

Peor caso del problema de monedas cuando existe la denominación 1: la cadena C → C−1 → C−2 → …. La tabulación tiene profundidad 1 siempre.

Problema 2 del taller

Escalera con costo mínimo

  • Desde el piso, el primer paso cae en el escalón 0 o en el 1.
  • Cada movimiento sube 1 o 2 escalones.
  • Se paga el costo de cada escalón que se pisa, incluido el último.

El enunciado no fija dónde se empieza ni dónde se termina. La salida 30 lo decide: con la meta más allá del último escalón daría 20; obligando a empezar en el 0, daría 40.

Problema 2 · las seis preguntas

La decisión se piensa hacia atrás

1 Estadoi, el escalón al que quiero llegar. Un solo parámetro — en monedas eran dos.
2 Significadof(i) = costo mínimo para llegar a pisar el escalón i, incluido su costo
3 Decisión¿Desde dónde llegué? Desde i−1 o desde i−2
4 Transiciónf(i) = costo[i] + min( f(i−1), f(i−2) )
5 Caso basef(0) = costo[0] · f(1) = costo[1]
6 Respuestaf(n−1)

«¿A dónde salto?»

Mira hacia adelante. Cada decisión abre caminos nuevos y no hay forma de escribir la respuesta en términos de algo más pequeño.

«¿Desde dónde llegué?»

Mira hacia atrás. Solo hay dos respuestas, las dos son subproblemas más pequeños, y la recurrencia sale sola.

Dos casos base porque la transición mira dos escalones atrás: desde el piso se entra directo al 0 o al 1.

Lo que solo la tabulación puede hacer

La tabla que se encoge

def escalera(costo):
    n = len(costo)
    prev2 = costo[0]
    prev1 = costo[1]
    for i in range(2, n):
        cur = costo[i] + min(prev1, prev2)
        prev2, prev1 = prev1, cur
    return prev1
O(n)tiempo, igual que antes
O(1)espacio, en vez de O(n)

f(i) solo mira dos casillas hacia atrás. Como el bucle avanza en orden, todo lo anterior ya no lo va a pedir nadie.

Esto no existe con memoización: el diccionario se llena en orden de descubrimiento, y en cualquier momento puede volver a pedirse una casilla vieja.

Problema 1 del taller

La misma recurrencia, escrita tres veces

1 · pura

def f(i, c, M):
  if c == 0: return 0
  if i == 0: return INF

  mejor = f(i-1, c, M)
  m = M[i-1]
  if c - m >= 0:
    mejor = min(mejor,
      1 + f(i, c-m, M))

  return mejor

2 · memoización

def f(i, c, M, memo=None):
  if memo is None: memo = {}
  if c == 0: return 0
  if i == 0: return INF
  if (i,c) in memo:
    return memo[(i,c)]
  mejor = f(i-1, c, M, memo)
  m = M[i-1]
  if c - m >= 0:
    mejor = min(mejor,
      1 + f(i, c-m, M, memo))
  memo[(i,c)] = mejor
  return mejor

3 · tabulación

def f(C, M):
  n = len(M)
  t = [[INF]*(C+1)
       for _ in range(n+1)]
  for i in range(n+1): t[i][0] = 0
  for c in range(1, C+1):
    for i in range(1, n+1):
      m = M[i-1]
      t[i][c] = t[i-1][c]
      if c - m >= 0:
        t[i][c] = min(t[i][c],
          1 + t[i][c-m])
  return t[n][C]

Tres ideas

1

Escriba la recurrencia antes que el código

Y dentro de la recurrencia, escriba primero la frase de la pregunta 2. Si no puede escribirla, todavía no entendió el problema.

2

Fuerza bruta y PD son la misma recurrencia

No son dos algoritmos. Son dos formas de evaluar la misma definición. Si tiene la recurrencia, la PD sale sola.

3

Memoización y tabulación difieren en el orden

La recursión lo descubre sola; en la tabla lo elige usted. De ahí salen la pila, la cobertura de estados y la compresión de espacio.
