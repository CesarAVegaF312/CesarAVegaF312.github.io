Taller de memoización · Estructuras de datos y algoritmos

El orden de la tabla

Memoización y tabulación resuelven los mismos estados, con la misma recurrencia y la misma complejidad. Suenan a dos técnicas distintas y no lo son. Lo único que cambia — y cambia todo lo demás — es quién decide el orden en que se llenan las casillas.

Con memoización, el orden lo descubre la recursión sola. Con tabulación, el orden lo elige usted, y tiene que acertar.

Arriba → abajo

Memoización. Arranca en el problema grande y baja pidiendo lo que necesita.

Abajo → arriba

Tabulación. Arranca en los casos base y sube llenando en un orden fijo.

Estado reutilizado

La casilla de la que depende el cálculo actual, ya resuelta antes.

02

Por qué el orden de la tabulación no es libre

La memoización nunca se equivoca de orden porque no elige ninguno: si necesita f(c−m), lo pide y espera. La tabulación no puede esperar a nadie — cuando llega a una casilla, lo que necesite ya tiene que estar escrito. Ese es todo el requisito, y esta figura lo muestra.

Cómo se detecta el error en la práctica. Si tabula en mal orden, el programa no falla: lee el valor inicial de la casilla (0, o infinito) y devuelve una respuesta silenciosamente incorrecta. Es el error más difícil de ver en programación dinámica. La prueba rápida: para cada término t[c−m] de su transición, pregúntese si el bucle ya pasó por c−m.

03

El muro que solo golpea la recursión

Las dos estrategias hacen el mismo trabajo, pero la memoización lo apila. Cada llamada pendiente ocupa un marco, y Python corta a las 1000 llamadas anidadas. La tabulación no apila nada: su profundidad es 1 sin importar el tamaño de la entrada.

04

La escalera, y la tabla que se encoge

Problema 2 del taller: costo mínimo para llegar al último escalón subiendo de 1 o de 2. Aquí la tabulación se gana algo que la memoización no puede dar: como el bucle avanza en orden y f(i) solo mira dos casillas hacia atrás, no hace falta guardar la tabla entera. Dos variables bastan.

La misma cuenta, sin tabla · espacio O(1)

Qué está pasando

La recurrencia

f(i) = {
  costo[0]        si i = 0
  costo[1]        si i = 1
  costo[i] +
    min( f(i−1),
         f(i−2) ) si i > 1
}
respuesta = f(n−1)

Esta compresión no existe con memoización. El diccionario se llena en orden de descubrimiento, no de izquierda a derecha, así que en cualquier momento puede volver a pedirse una casilla vieja. Solo cuando usted controla el orden puede afirmar «de aquí en adelante nadie va a mirar esa casilla» y botarla.

05

Cuál usar, y por qué

Ninguna es «la buena». Las dos tienen la misma complejidad asintótica: número de estados por costo de cada transición. La decisión se toma por otras tres razones — cobertura de estados, profundidad de pila y espacio.

Prefiera memoización

arriba → abajo · recursión + diccionario

  • Cuando solo se alcanza una parte de los estados. Con M = [3,7] y C = 20 visita 15 de 21 casillas; con M = [4,6] y C = 15, apenas 7 de 16. La tabulación llena todas, útiles o no.
  • Cuando el orden topológico es incómodo de escribir. Estados con varios índices, o transiciones que saltan, se vuelven un rompecabezas de bucles anidados. La recursión no lo necesita.
  • Cuando ya tiene la recurrencia. Es traducción casi literal: agregar el diccionario y dos líneas. Menos superficie para equivocarse.

Prefiera tabulación

abajo → arriba · bucle + arreglo

  • Cuando de todos modos va a visitar casi todos los estados. Ahí la recursión solo agrega costo: marcos de pila y búsquedas en el diccionario.
  • Cuando la entrada es grande. Es la única de las dos que no se estrella contra el límite de recursión, como se ve en el laboratorio 03.
  • Cuando el espacio importa. Controlar el orden es lo que permite botar lo que ya nadie va a mirar y bajar de O(n) a O(1), como en la escalera.

La misma recurrencia, escrita tres veces

Problema 1 del taller, en las tres formas. Las líneas verdes son la recurrencia: la transición y el caso base. Son la misma en las tres. Lo morado es lo único que agrega cada técnica.

1 · recurrencia pura

def monedas(C, M):
    if C == 0:
        return 0


    mejor = INF
    for m in M:
        if C - m >= 0:
            mejor = min(mejor,
                1 + monedas(C-m, M))

    return mejor

2 · memoización

def monedas(C, M, memo=None):
    if memo is None: memo = {}
    if C == 0:
        return 0
    if C in memo:
        return memo[C]
    mejor = INF
    for m in M:
        if C - m >= 0:
            mejor = min(mejor,
                1 + monedas(C-m, M, memo))
    memo[C] = mejor
    return mejor

3 · tabulación

def monedas(C, M):
    t = [INF] * (C + 1)
    t[0] = 0
    for c in range(1, C + 1):


        for m in M:
            if c - m >= 0:
                t[c] = min(t[c],
                    1 + t[c - m])

    return t[C]

El caso «NO ES POSIBLE». En las tres, un valor que sigue en INF al final significa que no existe combinación. Con M = [4,6] y C = 15 pasa exactamente eso: todo objetivo impar es inalcanzable. Devuelva el texto en la capa de salida, no dentro de la recurrencia — la recurrencia debe seguir devolviendo números para poder combinarse.
